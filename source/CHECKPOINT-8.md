# Checkpoint 8: aimed pitch paths and original scene positions

The native implementation now aims, rotates, stretches, samples, and extends
pitch paths. It also resolves the pitcher release position from the game's
decoded field-layout data. These calculations have been compared directly with
the original ARM code. This checkpoint is source and research, not a playable build.

## Implemented

- `pitch_path.c`: original arctangent lookup, handedness handling, relative control
  points, pitch rotation, depth scaling, target translation, Bezier/Cardinal
  sampling, and the three extra trajectory frames generated by UpdatePitch.
- `pitch_scene.c`: original pitcher-position conversion and release offsets for
  styles 0–10, including the alternate position flag.
- `extract_figure.py`: checked version-7 layout decoder with separate fence data.
  The normalized bytes preserve original ARM field offsets without native pointers.
- `test_figure_selection.py`: traces the original startup to its layout-load call.

## A confirmed asset-selection finding

The application startup passes `data/stadium.fig` to `CLx::Startup`, but that
function overrides its argument and calls `CCLFigureMgr::Load` with
`data/bb2011_480x320.fig`. The focused original-code trace confirms this call.
That particular 2011-named layout is used by II. This does not establish that
other 2011-named artwork is used.

`CLx::Startup` starts at ELF address `0xbdc9c`; the layout load is called at
`0xbdcb0`, targeting `0x962c8`. Its selected filename is at `0x1c3f34`.
The trace supplies an existing manager singleton and deliberately stops at Load;
it does not claim to have executed the entire application startup.

## Verification completed

| Check | Cases | Result |
|---|---:|---|
| Original arctangent lookup | 1,005 | Exact match |
| Full original UpdatePitch, extracted records and controlled scene | 369 | Controls, object writes, and 6,964 path vertices match |
| Styles, timing modes, mirror and coordinate-format combinations | 220 | Exact match |
| Version-7 figure decoding | 2 assets | Object bytes and fence data match original decoder |
| Full UpdatePitch with original scene-position code and decoded assets | 1,476 | Exact match |
| Startup layout selection | 1 focused trace | Selects bb2011_480x320.fig |
| Invalid and zero-depth path input | 11 | Rejected without output writes |

The 1,476 scene cases cover 369 records, two layouts, and both position flags.
738 cases use the confirmed active 480x320 layout; the other layout is extra
coverage, not a claim that it is selected in this release. Targets, timing-mode
test combinations, and position flags are controlled test inputs, not captured
live-match state. All generated path points and all transformed controls are
compared, including the three extrapolated frames. The original routine must
return normally; object bytes, output guards, and allocation lifetime are checked.

The full original UpdatePitch routine is executed. In controlled-scene cases,
GetDefensePos3D is substituted with a known test position; in the asset-based
cases, the original GetDefensePos3D and ToVirtual routines execute unchanged.
The development harness supplies memcpy, memset, and allocation/free operations.
It does not replace curve, matrix, arctangent, or aiming calculations with stubs.

The integrated native build used strict compiler warnings and
UndefinedBehaviorSanitizer with immediate failure. All listed pipeline tests
passed with that build on the x86-64 development host. Original ARM execution
is confined to development verification; the native code requires no emulator.

## Remaining work

The actual match-camera configuration, scene rendering, animation timing, and
pitch selection from match/player state remain to be connected. No batting,
contact result, fielding, or match progression is claimed. There is no new Windows
executable in this archive and no user testing is needed for this checkpoint.

The native API accepts an already resolved Q18 release point and target;
`bs2_pitch_release` provides the former from decoded layout data. Original invalid
or unsafe cases are rejected rather than reproducing out-of-bounds accesses or
zero-depth division. Inputs and outputs must use distinct buffers, sized according
to `pitch_path.h`.

## Reproduce

Provide Python with pyelftools and unicorn, plus GCC. Extract the II APK's
`lib/armeabi/libgameDSO.so` to `/tmp/baseball-game.so`. From this source directory:

```sh
gcc -std=c11 -O1 -g -fsanitize=undefined -fno-sanitize-recover=all -Wall -Wextra -Werror -shared -fPIC src/pitch_path.c src/pitch_curve.c src/projection.c src/pitch_scene.c -o /tmp/bs2-pitch-path.so
python test_pitch_path.py /tmp/baseball-game.so /tmp/bs2-pitch-path.so
python test_figure_selection.py /tmp/baseball-game.so
```

To regenerate the included layout fixtures:

```sh
python extract_figure.py /path/to/baseball-superstars-ii.apk figure-assets
```
